# 推定帯域幅通知による余分な再評価を抑える（1.10.2）

AndroidのNetworkCapabilities通知には、Wi-Fi等の推定上り・下り帯域幅の変動も含まれます。SIM Pilotはこの推定値を判定に使用せず、実際の通信品質は既存のプローブと無線情報で評価しています。

コールバックの公開状態（capability全フラグ、通信方式、信号強度、回線指定、所有UID、SIM一覧、transport情報、enterprise ID）を比較します。推定上り・下り帯域幅は比較対象から外します。この2値しか変わらなければ、追加の即時再評価を予約しません。フレームワークから渡された元オブジェクトは書き換えません。

検証状態、通信方式、回線指定、信号強度、その他の判定用公開情報を保持します。回線の出現・消失は従来どおり即時確認し、消失時には比較状態を破棄します。既定回線とモバイル回線の通知は個別に管理します。

定期監視・速度測定・切り替え条件・消灯時の停止・復帰時の再開・通信量キャッシュの周期は変更しません。Android 16/17のフックやバックエンドも置き換えません。

同じ実Android NetworkCapabilitiesを使い、帯域幅だけの連続通知、検証・信号・回線指定の変化、元オブジェクトの不変性、回線消失後の再出現をコマンドから検証します。実通信を作るテストや回線設定の切り替えではありません。

検証結果: Android 17実機の独立したapp_processテストで、帯域幅だけが変わる1,000件の通知は追加確認0件、検証・信号・SIM指定・一時停止・消失後の復帰は確認対象になることを検証しました。58件のJVMテスト、releaseビルド、release lint、整形チェックも通過しました。

SIM一覧は公開APIを使えるU Extension 12以降でのみ比較し、古い環境では回線指定と従来のSIM変更通知を維持します。transportInfoなど他の公開情報も変わった通知は保守的に再評価します。実回線切り替えの新たな比較試験と、端末全体のmAh測定は行っていません。
